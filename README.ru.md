# nvim-keys

Справочник по всем сочетаниям клавиш твоего Neovim: сгруппированы по плагинам,
показаны реальными нажатиями вместо сырой vim-нотации, с поиском и запуском
из панели.

[English version](README.md)

![окно nvim-keys](docs/screenshot.png)

## Зачем

`:map` выдаёт сотни строк и ничего не говорит о том, какой плагин что задал.
`which-key` помогает, только когда префикс уже известен. `nvim-keys` собирает
всё заранее — включая сочетания плагинов, которые ещё не загружены, — и даёт
искать по клавишам, описаниям и названиям плагинов.

- **Группировка по источникам.** Каждое сочетание отнесено к плагину, к твоей
  конфигурации или к самому Neovim.
- **Человекочитаемые клавиши.** `<C-/>` превращается в `Ctrl + /`, `<leader>bj`
  — в `Leader › b › j`; исходная запись остаётся строкой ниже.
- **Поиск по всему.** Клавиша, описание, команда, плагин, режим — сразу и в
  обеих нотациях (`ctrl+p` и `<C-P>` находят одно и то же).
- **Модуль для панели.** Waybar показывает счётчик сочетаний, клик открывает окно.
- **Русский и английский интерфейс**, выбирается по локали системы.

## Как это работает

`nvim-keys dump` запускает headless Neovim, загружает конфиг и дальше:

1. **Догружает все плагины lazy.nvim** (`require("lazy").load`) и вручную дёргает
   `VeryLazy`/`UIEnter` — в headless эти события не наступают, а LazyVim и
   подобные сборки вешают на них большую часть своих сочетаний.
2. **Запоминает источник каждого сочетания.** Prelude подключается через `--cmd`
   до конфига и оборачивает `vim.keymap.set` и `nvim_set_keymap`, снимая стек
   вызовов. Иначе сочетания со строковым `rhs` не отследить: их `sid` всегда
   указывает на `init.lua`, потому что подключённые через `require` lua-модули
   собственного script id не получают. Кадры-обёртки
   (`snacks.util.set_keymap`, обработчик keys в lazy.nvim, `vim/keymap.lua`)
   пропускаются, чтобы всплыл настоящий владелец.
3. **Читает key-spec'и lazy.nvim** (`p._.handlers.keys`) — это покрывает ещё не
   загруженные плагины, такие строки помечены меткой `lazy`.
4. Пишет результат в `~/.cache/nvim-keys/keymaps.json`.

Окно читает только этот JSON, поэтому открывается мгновенно. Кэш пересобирается
сам, если какой-то файл конфигурации Neovim новее него.

## Требования

- Neovim 0.9+ (разрабатывалось на 0.12)
- Python 3 с PyGObject, GTK 4 и libadwaita
- `jq`
- Опционально: Nerd Font для иконки в Waybar, сам Waybar, Hyprland

Arch: `pacman -S neovim python-gobject gtk4 libadwaita jq`

## Установка

```sh
git clone https://github.com/OneCOlyl/nvim-keys.git
cd nvim-keys
./install.sh          # копирует в ~/.local
./install.sh --link   # либо симлинки на этот каталог (для разработки)
nvim-keys dump
nvim-keys gui
```

Удаление — `./install.sh --uninstall`.

## Использование

| Команда | Что делает |
| --- | --- |
| `nvim-keys gui` | Открыть окно (пересоберёт кэш, если устарел) |
| `nvim-keys dump` | Пересобрать кэш сейчас |
| `nvim-keys waybar` | Вывести JSON для модуля Waybar |
| `nvim-keys list` | Текстовый список для терминала |
| `nvim-keys json` | Вывести сырой кэш |

В окне: печатаешь — идёт поиск, `Enter` копирует сочетание, `F1` объясняет
обозначения, `Ctrl+R` пересобирает, `Esc` закрывает.

### Waybar

Модуль из [`examples/waybar.jsonc`](examples/waybar.jsonc) добавь в свой
`config.jsonc`, стили из [`examples/waybar.css`](examples/waybar.css) — в
`style.css`, а `custom/nvim-keys` — в один из массивов `modules-*`. ЛКМ
открывает окно, ПКМ пересобирает кэш.

### Hyprland

[`examples/hyprland.conf`](examples/hyprland.conf) делает окно плавающим и
центрирует его (`class: dev.local.nvim-keys`), там же пример хоткея.

## Переменные окружения

| Переменная | Действие |
| --- | --- |
| `NVIM_KEYS_LANG` | `en` или `ru` вместо системной локали |
| `NVIM_KEYS_ICON` | Заменить глиф Nerd Font в модуле Waybar |
| `NVIM_KEYS_HOME` | Где лежат установленные lua/gui файлы |
| `NVIM_APPNAME` | Учитывается при поиске конфигурации Neovim |

## Ограничения

- Сочетания, привязанные к буферу и существующие только при открытом буфере
  (например, LSP), берутся из spec'а LazyVim; у других сборок их может быть
  видно меньше.
- Для сочетаний, созданных внутри многослойных хелперов, определение владельца
  эвристическое. В тултипе строки виден точный файл и номер строки, так что
  ошибку легко заметить.
- То, что плагин регистрирует только при определённом состоянии (открытый
  picker, активный терминал), в headless-сборе не видно.
